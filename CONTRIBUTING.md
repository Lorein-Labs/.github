# Guide de Contribution - Lorein Labs

Merci de l'intérêt que vous portez à nos travaux. Pour maintenir une rigueur d'ingénierie élevée, nous appliquons un protocole strict pour toute proposition de modification ou de collaboration.

## 🛠️ Philosophie de Travail

Toute contribution doit s'aligner sur notre triptyque de qualité :
1.  **Modularité :** Le code ou la documentation doit être réutilisable.
2.  **Preuve :** Toute modification doit pouvoir être validée par un workflow automatisé.
3.  **Traçabilité :** Chaque changement doit être documenté et justifié.

## 🤝 Comment Contribuer ?

### 1. Signalement d'Anomalies (Issues)
Si vous identifiez une erreur dans nos modèles de simulation ou nos blueprints publics :
- Ouvrez une **Issue** en décrivant précisément le comportement attendu vs le comportement observé.
- Fournissez un contexte technique (environnement, version, logs).

### 2. Propositions de Modifications (Pull Requests)
Pour soumettre du code ou des améliorations :
- **Forkez** le dépôt concerné.
- Créez une branche descriptive (ex: `feat/nouvelle-simulation` ou `fix/erreur-logique`).
- Assurez-vous que votre code respecte les standards de **Linting** définis dans l'organisation.
- Accompagnez votre PR d'un résumé des tests effectués.

### 3. Experts Métiers & Consultants
Pour les collaborations stratégiques ou les audits de systèmes, merci de ne pas soumettre de code sensible via GitHub. Contactez-nous directement via le profil principal pour établir un cadre de travail sécurisé (NDA).

## 🚫 Règles de Conduite

- **Respect des Standards :** Les messages de commit doivent être explicites (standard *Conventional Commits* recommandé).
- **Sécurité :** Ne soumettez jamais de clés API, de mots de passe ou de données nominatives dans vos contributions.
- **Validation :** Aucune modification n'est fusionnée sans avoir passé avec succès la totalité des workflows de simulation de l'organisation.

## ⚖️ Droits et Licences

En contribuant à ce projet, vous acceptez que vos contributions soient placées sous la licence spécifique au dépôt visé (voir le fichier `LICENSE` du dépôt correspondant).
